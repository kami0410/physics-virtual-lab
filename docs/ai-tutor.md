# AI 助教使用说明

助教的作用是：**做实验卡住时，帮你找到真正的原因，讲清道理，只把出问题的那一项调好**，让你自己接着做下去。它不会替你把整个实验做完，也不会替你往数据表里填读数。

## 打开助教

进入任意一个实验，点顶栏的 **助教** 按钮，右侧会弹出助教面板。再点一次按钮、或面板右上角的 ✕ 关闭。

如果你在某一步停留超过 4 分钟、短时间内触发了好几次仪器警告，或者“自动完成”没能做完这一步，助教按钮会亮起来提醒你。

## 离线检查（不用配置）

面板上半部分的“**现在的情况**”不需要联网，也不需要任何设置，打开就能用。它会检查：

- 这一步需要的器材是不是都放上台了；
- 光斑、读数、开关状态等是否满足这一步的要求（各实验有专门的检查，例如“参考光斑偏离干板中心 1.8 cm”）；
- 数据表里还有哪些读数没填；
- 你最近的操作里有没有把前面调好的东西又弄乱了。

能直接修正的条目后面有一个按钮，点一下就会把那一项调好。下面还有三个按钮：

| 按钮 | 作用 |
|---|---|
| 看本步提示 | 显示这一步的操作要点 |
| 重新检查 | 调整之后再检查一遍 |
| 让助教接手本步 | 先把前面被改乱的设置恢复，再按规范操作完成这一步。实在做不下去时用 |

## 接入大模型

接入以后，可以在面板下方的输入框里直接提问，例如：

- “为什么屏上看不到条纹？”
- “下一步该调哪个旋钮？往哪边调？”
- “我测出来的 g 偏大了 3%，可能是什么原因？”

助教能看到实验的当前状态（每个仪器的参数、数据表、本步的完成条件）和你**从开始到现在的操作记录**，所以它会针对你的具体情况回答，比如“你在第 2 步把物距调到了 18.0 cm，小于焦距，所以成虚像，屏上找不到像”。需要时它会直接转动旋钮、放置器材，你能在三维场景里看到它在调哪个。

### 设置步骤

1. 在助教面板右上角点 **设置**；
2. “服务”里选一个（下表），接口地址和模型名会自动填好；
3. 填入从服务商那里申请的**密钥**（本机模型不需要）；
4. 点 **测试连接**，看到“连接成功”后点 **保存**。

模型名可以改成服务商当前提供的任何型号。助教要调用工具（读状态、转旋钮），所以请选**支持工具调用（function calling）**的模型，主流服务的主力模型都支持。

### 本机模型（免费、不联网）

在自己电脑上跑开源模型，不花钱、不需要密钥、数据不出本机。需要电脑有 8 GB 以上内存，有独立显卡会快很多。

**Ollama**

1. 到 <https://ollama.com> 下载安装；
2. 打开命令行，下载一个支持工具调用的模型，例如：
   ```bash
   ollama pull qwen2.5:7b
   ```
3. 在助教设置里选“本机 Ollama”，测试连接、保存。

用**一键启动**（或 `npm run dev`）打开实验室时，到此就可以用了。如果用的是**离线单文件版**或网站版，Ollama 默认会拒绝网页的请求，还需要设置一个环境变量后重启 Ollama：

- Windows：先在任务栏右下角退出 Ollama；打开“设置 → 系统 → 系统信息 → 高级系统设置 → 环境变量”，新建用户变量 `OLLAMA_ORIGINS`，值为 `*`；再启动 Ollama。
- macOS：终端里运行 `launchctl setenv OLLAMA_ORIGINS "*"`，然后退出并重新打开 Ollama。

**LM Studio**

1. 到 <https://lmstudio.ai> 下载安装，在里面下载一个模型；
2. 进入 Developer（开发者）页，启动本地服务器；在 Server Settings 里打开 **Enable CORS**；
3. 在助教设置里选“本机 LM Studio”，模型名填 LM Studio 里显示的模型标识。

## 中转是什么，什么时候需要

浏览器出于安全考虑，只允许网页访问明确“欢迎网页访问”的接口（跨域许可，CORS）。大部分大模型服务都允许，但**智谱 GLM 只允许它自己的网页访问**；另外有些服务在出错时不带跨域许可，浏览器就只能看到一个笼统的“网络错误”，看不到真正的原因。

中转是一个运行在你自己电脑上的小程序（`tools/ai-relay.mjs`），把助教的请求原样转给服务商，再把回应原样交还给页面，同时补上跨域许可。**助教会自动发现并使用它，不需要改任何设置。**

| 你怎么打开实验室 | 中转 |
|---|---|
| 一键启动 / `npm run dev` / `npm run preview` | 已经内置在同一个服务器里，什么都不用做 |
| 离线单文件版、网站版 | 需要时在项目文件夹里运行下面的命令 |

```bash
npm run relay              # 在当前窗口运行，关掉窗口就停止
npm run relay:install      # 设为开机自动在后台运行，并立即启动
npm run relay:uninstall    # 取消开机自启，并停止后台中转
```

`relay:install` 会把中转复制到用户目录（Windows：`%APPDATA%\physlab-ai-relay`），所以之后移动或删除项目文件夹也不影响。

**安全性**：中转只监听本机 `127.0.0.1:8787`，别的电脑连不上；默认只转发到上表这些大模型服务的地址；密钥由浏览器随每次请求带来，中转不保存密钥，也不记录对话内容（窗口里只显示时间、服务地址、状态码）。

高级选项：

```bash
node tools/ai-relay.mjs --port 9000                # 换端口
node tools/ai-relay.mjs --allow api.example.com    # 额外放行某个服务
node tools/ai-relay.mjs --any                      # 放行任意 https 服务
```

系统设置了 `HTTPS_PROXY` 环境变量时，中转会经这个代理访问外网（需要 Node.js 24 以上）。

## 隐私：哪些数据会发出去

- **密钥**只保存在你这台电脑的浏览器里（localStorage），请求由浏览器直接发给你选的服务商（或经过你本机的中转），不经过任何第三方服务器。本项目没有任何服务器。
- 提问时发给模型的内容：本实验的原理摘要、实验当前状态（仪器参数、数据表、本步要求）、你在本实验中的操作记录，以及你输入的问题。**不包含任何个人信息。**
- 不想把任何数据发出去，就不要接入大模型，或者用本机模型。离线检查功能完全在本机运行。

## 连不上怎么办

点“测试连接”后，失败时会显示原因。常见的有：

| 提示 | 原因与处理 |
|---|---|
| HTTP 401 / 403（密钥无效或没有权限） | 密钥填错、过期，或账户没有开通这个模型 |
| HTTP 404（地址或模型名不对） | 检查模型名的拼写；自定义服务检查接口地址（通常以 `/v1` 结尾） |
| HTTP 429（请求太频繁或额度用完） | 稍等再试，或到服务商那里查看余额 |
| 浏览器没有收到应答，也没有找到本机中转 | 先确认网络正常；然后用一键启动打开实验室，或运行 `npm run relay`，中转会把服务商返回的真实错误显示出来 |
| 连不上本机 Ollama | 确认 Ollama 在运行；单文件版需要设置 `OLLAMA_ORIGINS`（见上文） |
| 本页面是 https 网页，禁止访问 http 地址 | 网站版不能访问 http 的远程地址，换成 https 地址 |
| 网页版询问“是否允许访问本地网络上的设备” | 用网站版连接本机模型或中转时会出现，选“允许” |

模型回答了但不调旋钮：换一个对工具调用支持更好的模型（小参数量的本机模型有时只会说、不会调）。
